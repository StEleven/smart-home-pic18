# SH1 串口协议约定

配套智慧小屋 v1.2 固件与3D上位机使用此协议，兼容 v1.1。软件实现与实物联调状态分别记录。平台为 DM164150 + EV58G97A；湿度、雨滴、水浸来自实际输入，门窗帘风口采用舵机、家电与制冷采用板载显示模拟。

## 传输与帧格式

串口为 **115200 baud、8 数据位、无校验、1 停止位、无流控**。主机打开串口后置 DTR 为开启；实际 USB 转串口模块是否把 DTR 接到复位电路，现有资料未指定，不能据此认定板卡一定复位。

每帧为 ASCII 文本：帧头为 `SH1|KIND`，其后可接零个或多个 `|key=value` 字段，以 LF（`0x0A`）结束。发送端使用 LF；主机接收兼容 CRLF。完整帧最多 **1024 字节，包含结束符**。串口接收必须遇到 LF 才提交一帧；解析函数单独使用时也可接受已去掉结束符的单帧。

- `SH1` 与消息类型区分大小写。消息类型仅允许下表所列名称。
- 字段名匹配 `[a-z][a-z0-9_]{0,31}`；字段值只能含 ASCII 可打印字符，不能含 `|`、`=` 或控制字符；没有转义规则。
- 不允许重复字段、无等号字段或空字段值；唯一空值例外是 `CAPS` 消息的 `caps=`，表示只读固件。
- 字段顺序不限。未知的合法 STATE 字段会保留；已定义字段不能缺失。非法消息整帧丢弃并记录异常；超长帧持续丢弃至下一 LF，随后恢复接收，不把其尾部当成新帧。
- 数值使用十进制整数字符串，不接受小数、正号或空白。无符号字段不接受负号。`?` 只用于下表允许未知的字段。

## 消息与会话

| 类型 | 方向 | 字段与处理 |
| --- | --- | --- |
| `HELLO` | 主机 → 板端 | `nonce` 为32位十六进制随机令牌，请求协议握手。未握手时主机约每 2 秒重发；超过 5 秒仍无握手时显示等待兼容固件。 |
| `CAPS` | 板端 → 主机 | 必须有 `boot`、`firmware`、`caps`；声明session时还须回显当前`client`。主机记录启动标识、固件版本与能力，随后发送 `GET`。 |
| `GET` | 主机 → 板端 | 无字段，请求一份新的完整 `STATE`。 |
| `STATE` | 板端 → 主机 | 必须包含下一节全部字段。必须完成握手、`boot` 匹配且序号向前推进，才成为有效实时状态。 |
| `CMD` | 主机 → 板端 | `boot`、`id`、`action`、`value`；协商session后增加`client`，请求板端执行操作。 |
| `ACK` | 板端 → 主机 | `boot`、`id`、`result=ok/rejected`；session会话须回显CMD的`client`；建议同时提供非空 ASCII `reason`。当前主机允许省略 `reason`。 |
| `EVENT` / `ERR` | 板端 → 主机 | 当前会话 `boot`，以及 `reason` 或 `code`；仅记录、显示，不修改 STATE，也不代替 ACK。 |
| `PING` / `PONG` | 保留 | 解析器识别名称；当前控制器没有发送、应答或保活实现。 |

`boot` 是板端每次启动应更换的会话标识，须匹配 `[A-Za-z0-9_.:-]{1,64}`；同一次启动内保持一致。配套主机每次连接或状态过期/检测重启后生成新`nonce=uuid4.hex`，同一次待握手的HELLO重试复用该nonce；PIC仅在本次启动后的第一个合法 HELLO 采纳 nonce 作为 boot，此后 HELLO 继续返回同一 boot，直到 MCU 重启。主机重连可以接收板端仍在使用的旧 boot。首次握手前不执行 CMD；重启后旧 boot 的 CMD 不能执行。boot不是硬件序列号；兼容旧无nonce主机时固件可使用启动计时令牌，但当前配套主机始终发送nonce。`firmware` 是非空 ASCII 固件版本。`caps` 是逗号分隔的能力名称，无附加空格；可为空。主机仅启用其认识且固件声明的能力，未知能力名称不启用操作。只读固件仍须提供完整 STATE；不具备的传感或输出字段按表使用 `?` / `unknown`。



`session`是协议能力标记，不是设备动作。配套固件CAPS声明`session`并回显`client=当前HELLO nonce`；主机忽略缺少/不匹配当前client的session CAPS，不激活控制。协商后CMD附client，主机只接受boot、id、client均匹配待确认请求的ACK；旧固件未声明session时仍发送原4字段CMD，接受原ACK。

MCU的boot在首次绑定后保持稳定；同nonce的重复HELLO保留板端命令缓存，新nonce绑定新client并清除旧client缓存。板端拒绝旧client的CMD（CLIENT_MISMATCH），同client下重复同id不能重复执行；缓存ACK只回显对应CMD的client。已启用session的板端不会因无nonce的旧HELLO降级。状态超过2秒过期时，主机保留旧快照、禁控并清除待确认请求，换client重新HELLO；这也允许MCU在运行中复位后重新完成首次握手，期间不重发旧CMD。

板端应主动周期发送完整 STATE；配套v1.1固件每500 ms发送一次；其他兼容固件的正常快照间隔必须小于主机的2秒过期时限。主机当前在握手、ACK 和命令超时后发送 GET，没有持续轮询 GET。超过 2 秒未收到新的有效 STATE，显示旧值但标为过期并禁用控制；错误帧、重复帧、ACK 和 EVENT 都不能刷新状态时限。

`seq` 在同一 `boot` 内按无符号 32 位递增并回绕。主机计算 `delta=(new-old)&0xffffffff`，仅接受 `0 < delta < 0x80000000`；重复、逆序或过旧快照不覆盖当前状态。新 `boot` 的 CAPS 清除旧状态、序号与待确认请求；STATE 中出现不同 `boot` 时，主机先禁用控制并重新 HELLO，等待新握手。

## 完整 STATE 字段

每条 STATE 都要发送全部 26 个字段；不使用增量补齐。表中的 `?` 是字面值，表示未知，不是缺省值。

| 字段 | 单位、合法值及含义 | 允许未知 |
| --- | --- | --- |
| `boot` | 当前启动标识，规则见上文 | 否 |
| `seq` | 0～4294967295，快照序号 | 否 |
| `uptime` | 0～4294967295，启动后整秒数；32 位回绕 | 否 |
| `temp` | -400～1250，0.1°C，即 -40.0～125.0°C | `?` |
| `humid` | 0～1000，0.1%RH，即 0～100.0%RH | `?` |
| `lux` | 0～200000，lx | `?` |
| `rain` | 0 干燥，1 雨湿 | `?` |
| `water` | 0 无水浸，1 水浸 | `?` |
| `door` | 0 软件输出开启/运动中，1 软件输出关闭；不是实测反馈 | `?` |
| `window` | 0 软件输出开启/运动中，1 软件输出关闭；不是实测反馈 | `?` |
| `window_target` | 0～100，窗目标开度；0 关闭、100 全开 | `?` |
| `curtain` | 0～100，窗帘输出开度；0 关闭、100 全开 | `?` |
| `vent` | 0～100，空调风口输出开度；0 关闭、100 全开 | `?` |
| `living` | 0～100，客厅照明亮度百分比 | `?` |
| `bedroom` | 0～100，卧室照明亮度百分比 | `?` |
| `hall` | 0～100，过道照明亮度百分比 | `?` |
| `load_keep` | 0 关闭、1 开启，常供电负载输出状态 | `?` |
| `load_switch` | 0 关闭、1 开启，可切换负载输出状态 | `?` |
| `cooling` | 0 停止、1 开启，制冷输出使能 | `?` |
| `demand` | 0 无需求、1 有需求，制冷需求输入 | `?` |
| `scene` | `home`、`away`、`long_away`、`sleep`、`movie`、`ktv`、`unknown` | `unknown` |
| `control` | `auto`、`manual`、`unknown`；仅描述窗控接管方式 | `unknown` |
| `manual_ms` | 0～600000，窗控手动接管剩余毫秒 | 否 |
| `timer` | `idle`、`running`、`paused`、`done`、`unknown` | `unknown` |
| `timer_s` | 0～86400，学习计时剩余秒数 | 否 |
| `muted` | 0 未静音、1 当前水浸报警已静音 | `?` |

**STATE 没有单独的传感器采样时间或有效位。** 传感器未安装、读取失败或数据已过期时，板端必须在每一条快照中对相应字段发送 `?`，不能重复旧读数把快照伪装为有效测量。主机只检查帧与字段值，不能根据新的 `seq` 判断各传感器是否真的重新采样。

输出开度、使能、门窗状态和ACK均不证明机构已到位或负载已实际通电。本项目不使用门磁；`state_source=commanded`明确门窗状态来自软件输出指令。门窗从关闭目标推进到关闭输出指令后可报告1，显示仍必须标注软件输出状态。协议不提供实测位置或上锁反馈。旧固件未声明state_source时，界面标为来源未声明，不自动声称实测。

### 可选门目标扩展

`door_target` 是可选 STATE 字段，合法值为十进制整数 `0`～`100` 或 `?`。0 表示关闭目标，100 表示全开目标；它只代表输出目标，不代表实测角度、闭合反馈或上锁状态。旧固件可省略，原 26 个必需字段不变；省略时界面显示“目标未提供”，不按门磁推断角度。出现非法数值时整条 STATE 拒绝。

v1.1声明`door`能力并接受`door=open/close/auto`。真实与离线模式均经同一请求入口；离线专用`set_actuator('door', value)`仍保留用于任意百分比演示，不发送串口CMD。默认门窗状态跟随模拟输出；显式模拟反馈可独立覆盖为0/1/?，界面必须标注为模拟故障注入。百分比表示软件指令，不是实测舵机角度。

其他可选STATE扩展：`state_source`仅允许`commanded`；`comfort`为0未知、1偏干、2舒适、3偏湿，按湿度<40%、40%～60%、>60%分类；`alarm`为0/1，水浸报警锁存，采样未知时保留，确认water=0时解除；`setpoint10`为200～320（0.1°C）或`?`，显示板载电位器设温；`ktv_brightness`为0～100，省略时按50；`demand_mode`为`auto/on/off`，声明`demand_hold`时分别表示自动/持续手动开/持续手动关。缺少可选字段的旧26字段快照仍有效；已知可选字段非法则整帧拒绝。

## 能力与命令

主机发送CMD时带当前握手boot、本地递增十进制id；协商session时另带当前client；同一时间只保留一条待确认命令。必须同时满足状态未过期、无待确认命令、固件声明相应能力，才能发起操作。

| `caps` 能力 | `action` | `value` |
| --- | --- | --- |
| `scene` | `scene` | `home` / `away` / `long_away` / `sleep` / `movie` / `ktv`（另需 `ktv` 能力）；模拟器也接受 `unknown`，界面不将其作为日常场景选项 |
| `door` | `door` | `open` / `close` / `auto` |
| `demand` | `demand` | `0` / `1` / `auto`；声明 `demand_hold` 时持续手动关闭/开启，或恢复自动 |
| `window` | `window` | `open` / `close` / `auto` |
| `curtain` | `curtain` | `open` / `close` / `auto` |
| `lights` | `living` / `bedroom` / `hall` | 0～100，或 `auto` |
| `light_effect` | `light_effect` | `warm` / `rainbow` / `pulse` / `party`；灯效命令仅KTV允许，其他场景拒绝 `SCENE` |
| `ktv` | `ktv_brightness` | 0～100，KTV八灯统一总亮度；其他场景拒绝 `SCENE` |
| `loads` | `load_switch` | `0` / `1`；没有关闭常供电负载的命令 |
| `mute` | `mute` | `1`，仅静音当前水浸报警 |
| `night` | `night` | `1`，仅sleep开启30秒10%走道起夜灯；不覆盖走道手动接管 |
| `timer` | `timer_start` | 1～86400，计时秒数 |
| `timer` | `timer_pause` / `timer_resume` / `timer_stop` | `1` |

板端必须检查 CMD 的 `boot` 与参数、能力及安全条件，不能仅因主机按钮可用就直接驱动输出。ACK 回传原 `boot`、`id`：`ok` 只表示板端已接受，`rejected` 表示拒绝。当前主机只处理匹配当前启动、当前待确认请求，以及协商后相同client的ACK；收到后清除待确认状态并 GET，执行结果以随后 STATE 为准。

发送失败、发送不完整、断线、重启或约 2 秒内未收到匹配 ACK，均不能据此断言“没有执行”。发送失败和 ACK 超时时主机提示结果未知；断线或启动变化使旧待确认请求失效。超时时清除待确认请求；状态仍有效时发送GET，同时状态已过期则进入重新握手，**不自动重发CMD**。超时后迟到的 ACK 不会重新确认已经清除的请求。板端应保证任何请求都不会绕过安全条件；跨启动的旧命令不得执行。

模拟器使用的原因码为 `OK`、`INVALID_VALUE`、`UNSUPPORTED`、`RAIN`、`RAIN_UNKNOWN`、`LONG_AWAY`、`AWAY`、`NO_WATER_ALARM`、`TIMER_STATE`、`SCENE`。主机对认识的原因码显示中文，其他合法 ASCII 原因码按原文显示。

## 板端责任与离线演示边界

真实板端独立完成采样、场景与手动接管、执行器输出、软件状态检查、报警和学习计时；主机断开后规则仍需工作。真实湿度、雨滴、水浸只能来自板端；上位机的模拟输入入口在真实会话中拒绝调用。未知采样必须报`?`，不得把模拟数据或上次读数冒充新测量。

配套规则与离线演示：

- 门自动：home跟随板载Presence，其他场景关闭；离线home使用虚拟有人示意。手动开关接管60秒，auto立即恢复。普通/长期离家均拒绝开门。切场景清除手动接管。门窗状态来自输出指令，离线显式模拟反馈可以覆盖状态作故障演示。
- 自动窗：home/away且温度>=30.0°C、雨滴干燥、无制冷需求时自然通风。雨湿、雨滴未知或long_away强制关闭，取消窗手动；雨停重新判断，不重放旧开窗命令。普通away不锁窗。
- 制冷：自动需求按电位器设温20.0～32.0°C，旋钮无效默认31.5°C；温度达到设温+0.5°C进入、低于等于设温-0.5°C退出。自动模式要求温度有效、需求为1、窗目标及输出关闭、场景为home/sleep/movie/ktv；温度未知时auto需求未知并停止制冷。声明`demand_hold`后，`demand=1`持续强制开启，忽略设温、温度未知和开窗条件；`demand=0`持续关闭；`auto`恢复自动。home/sleep/movie/ktv切换保留手动模式；进入away/long_away恢复auto并关闭制冷，这两场景拒绝手动开启。`demand`仍为当前0/1/?需求，`demand_mode`报告模式。风口随制冷输出0/100。无`demand_hold`的旧固件界面标为临时需求控制。
- 窗帘：home/away光照>=500 lx连续3秒自动关闭，<=300 lx连续3秒打开，中间区间保持；sleep/movie/ktv/long_away关闭。0关闭、100全开。光照未知保留上次输出。窗、门、窗帘、每灯区独立手动接管60秒，场景切换清除。control/manual_ms只报告窗；可选door_manual_ms/curtain_manual_ms/living_manual_ms/bedroom_manual_ms/hall_manual_ms为0～600000毫秒，away_check_ok及night为0/1；均可省略，若存在则必须合法。
- 离线灯光场景预设（演示假设，实际板端另按光照规则；客厅/卧室/走道%）：home为70/40/30，movie为20/0/10，其他为0/0/0。night=1仅sleep开启30秒10%走道起夜灯，night字段为0/1；走道手动接管优先，切场景清除起夜计时。普通离家进入时关闭可切换负载及灯光，随后允许手动开启；long_away持续禁止开启；保留负载保持1。
- 普通场景仅日常暖光。进入KTV默认关闭门、窗、帘，随后允许显式手动控制，Presence不自动开门。进入KTV默认`rainbow`；退出恢复`warm`。总亮度`ktv_brightness`复位默认50，切场景保留，0使八灯全灭；KTV的`living/bedroom/hall`均报告总亮度，动画不改变STATE。KTV拒绝单独灯区命令`SCENE`，三个房间入口均使用`ktv_brightness`。
- 可选`light_effect`为`warm/rainbow/pulse/party`，缺省暖光；`CAPS light_effect`允许灯效命令，`CAPS ktv`允许KTV场景与总亮度。每次切换灯效或进入KTV从elapsed=0开始。rainbow沿用256步色轮，每24ms前进一步，相邻像素偏移32；RGB各分量乘总亮度/100向下取整。pulse使用同一颜色，另加2400ms三角呼吸，增益10%～100%，先将总亮度乘增益/100取整，再缩放RGB。party每180ms换一拍：`beat=floor(elapsedMs/180)%256`、`lead=(beat*5)&7`；仅lead、(lead+3)&7、(lead+5)&7点亮，色相为`(beat*53+index*71)%256`。三维展示使用本地接收灯效的时间起相位。
- 学习`timer_start`只开始计时，不改变窗帘。非KTV、非离家时，第8灯（index7）独立白光呼吸：以timer_start为起点，4000ms三角周期，亮度10%～60%；暂停为20%白色常亮，完成或停止恢复该灯原暖光。KTV整圈灯效优先，离家不叠加学习灯；学习灯不改变房间亮度STATE。

- 水浸静音仅作用于当前湿事件，water=0确认解除后复位，water=?保持报警及消音；无报警时拒绝消音。计时可开始、暂停、恢复、完成、停止。湿度舒适提示无效时为0。
- 离线门窗默认即时跟随软件指令，不模拟实物运动耗时；可固定显式模拟反馈0/1/?并用auto解除覆盖。该输入接口不属于串口命令，不能改变真实传感器。

舵机角度、接线、电平与传感器标定以固件配置及后续用户硬件验收为准。离线模拟、软件测试与构建结果不能记为实物功能通过。原基础实验的独立阈值与本SH1扩展温控配置分开保留。
