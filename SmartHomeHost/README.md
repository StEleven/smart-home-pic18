# 智慧小屋上位机

默认启动彩色交互式3D小屋：拖动旋转、缩放、俯视、屋顶/外墙切换，门、窗、窗帘、风口与灯光随控制状态同步。采用React、Three.js与本地模型，Qt WebEngine承载，Qt WebChannel连接Python串口控制器。旧二维界面仅作为`--legacy`诊断入口保留。

主机侧已实现3D展示、SH1协议、能力控制、会话隔离、状态过期保护、ACK与超时处理、离线规则及CSV记录。配套固件见 [SmartHomeStuFull](../SmartHomeStuFull)。

## 启动

在 Windows 上安装 64 位 Python 和 Node.js，在本目录用 PowerShell 执行 `./setup.ps1` 安装依赖并构建前端，然后双击 `启动上位机.cmd` 或 `启动离线演示.cmd`。验证环境为 Python 3.14.3、PySide6 6.12.0、Node.js 24.14.1。

```powershell
./.venv/Scripts/python.exe run.py --demo
./.venv/Scripts/python.exe run.py --legacy
```

3D程序加载本地构建的 `frontend/dist`；演示无需联网或启动 Node.js。修改前端后可在 `frontend` 目录重新构建：

```powershell
npm ci
npm run check
npm run build
```

## 使用与数据含义

顶端切换回家、普通离家、长期离家、睡眠、观影、KTV；点选场景设备或右侧下拉菜单操作。支持门/窗/帘开关及恢复自动、分区灯光、睡眠场景30秒10%起夜照明（走道手动接管优先）、模拟家电、水浸消音、学习计时、空调自动/手动开启/手动关闭。旋钮设温和湿度舒适提示来自固件快照；旧固件缺少可选字段时显示未提供。

普通场景使用日常暖光。进入KTV，门窗帘默认关闭；随后仍可手动打开。选择任一房间照明入口，可切换流动彩虹、彩色呼吸、节拍跳色，并调节同一个KTV总亮度；0%使八灯全灭，退出KTV恢复暖光。总亮度默认50%，切场景保留。旧固件未声明`ktv`时禁用KTV按钮。

空调“手动开启/手动关闭”持续保持，居家场景切换保留；进入普通/长期离家恢复自动，离家不能手动开启。自动仍按旋钮设温和±0.5°C滞回、关窗条件控制。旧固件未声明`demand_hold`时显示“临时开启/临时关闭”。

学习计时开始后台灯慢呼吸，暂停时常亮；完成或停止恢复原照明，窗帘保持原状态。KTV灯效优先，计时继续。

门窗帘风口由舵机模拟；灯光、制冷与家电由板载灯/显示表示。本项目不采购门磁。`state_source=commanded`表示门窗状态来自软件输出指令，3D动画表示目标/输出；均不证明实测位置、到位或上锁。门窗运动完成的判定仅是软件输出推进，不是物理反馈。

模拟实验页只在离线会话允许注入温湿度、雨滴、水浸、光照及门窗状态。默认门窗状态跟随指令；覆盖0/1/?可演示输出与模拟反馈不一致，再选“跟随动作”释放。真实会话拒绝这些输入，真实测量不能由UI伪造。门的离线百分比滑块也不会发送串口命令。

主要联动：雨湿/未知及长期离家关窗；普通离家允许自然通风，禁止开门与制冷。门auto跟随回家Presence，KTV保持关闭。窗帘强光遮阳、睡眠/观影/KTV隐私；门窗帘和普通灯区手动接管60秒。离线灯光使用场景预设，实际板端按环境光调节。制冷auto采用20～32°C旋钮设温及±0.5°C滞回，默认31.5°C；自然通风30°C、窗帘500 lx关闭/300 lx打开、连续3秒确认。

## 接真实板卡

平台是PIC18F57Q43 Curiosity Nano（DM164150）与Curiosity Nano Explorer（EV58G97A）。通过Nano USB选择对应COM口连接，固定115200/8N1、无流控、DTR开启。固件须实现[SH1协议](PROTOCOL.md)，握手声明能力并持续发送完整STATE；v1.1按500 ms更新，未声明能力的操作禁用。

主机每次连接/恢复握手生成随机nonce，同一握手的重试复用nonce；固件首次握手采纳为boot令牌，同次启动重连仍用原boot。声明session能力后CAPS回显当前client，CMD/ACK绑定同一client，旧固件保持原协议兼容。超过2秒无新有效状态禁用控制并换client重新握手，保留旧快照；ACK只表示请求接受，随后STATE决定显示。ACK超时在状态有效时查询状态、过期时重新握手，均不自动重发CMD；重连不重放旧请求。真实规则由板端独立维持，主机断开仍应工作。

SHT30湿度、雨滴DO、水浸DO及舵机实际接线、供电、电平、读数和动作需要用户在硬件上验收；软件未生成任何实物通过记录。

## 记录与软件检查

断开/切换/关闭自动保存CSV到`logs/simulation/`或`logs/real/`，亦可导出当前会话。来源、时区时间、固件、boot、请求响应和原始STATE分别记录。主机最多保留20000条记录，3D侧显示最近60条事件；长实验应分段导出。自动保存失败保留记录并暂停切换，手动导出成功后继续。异常写入`logs/application_errors.log`。

```powershell
./.venv/Scripts/python.exe -B -m unittest discover -s tests -v
```

测试使用离屏 Qt、串口替身和临时目录，覆盖串口请求、随机握手令牌、可选字段、输出状态与模拟反馈、温控滞回及离家限制。在 `frontend` 目录运行 `npm run test:scene` 可检查 3D 场景的状态更新和动作映射。

模块：`web_window.py`承载3D，`bridge.py`验证前后端操作，`controller.py`管理串口与会话，`protocol.py`校验帧，`simulator.py`提供独立演示；`frontend/src/scene`为3D模型、动画与绑定。
